대학교에서 컴퓨터공학을 전공하여 데이터베이스, 운영체제, 네트워크, 알고리즘 등 기본이론들을 학습했습니다. 2학년 때 프론트 웹 쪽에 관심을 가져 개인 프로젝트를 간략하게 진행하였습니다. 단일 html, css로 디자인을 하였고 처음으로 FileZilla를 활용하여 웹 호스팅을 한 경험이 있습니다. 이 과정을 통해 스스로 호스팅에 대한 정보를 찾아본 것은 도움이 되었습니다. 그리고 점차 서버에 대한 개념이나 백엔드 쪽의 개념도 필요하게 되면서 node.js를 통해 서버 소켓 통신에 대해 학습하였고 점차 팀 프로젝트로 발전하였습니다. 
 졸업 작품은 센서 게임 허브라는 주제로 진행을 했고 저는 프론트엔드와 DB 파트를 담당했습니다. DB 파트를 구현하던 중 권한 설정에 대한 혼란이 발생하였고 접근할 수 없는 사용자가 다른 사용자의 정보에 접근하는 문제가 발생하였습니다. 이를 Supabase RLS 정책을 적용하여 사용자별 접근 권한을 명확화하여 다른 사용자가 내 정보에 접근할 수 없게 보안을 강화하였습니다.
 한편 한국정보교육원의 풀스택 개발과정에 참여하여 2차 프로젝트에 편의점 플랫폼을 주제로 진행을 하였고 저는 위치 지도 API 부분을 담당하였습니다. 지도 API는 네이버 지도 API를 활용하였으며 매장의 위치 정보 및 사용자의 위치 정보를 파악하는 기술을 구현했습니다. 이 때 네이버 지도 정책상 개인 프로젝트를 위해서는 Proxy 서버를 따로 실행하여 접근을 하지 않으면 API를 이용할 수 없어 Proxy 서버를 따로 실행하여 지도 기능을 수행했습니다.
 3차 프로젝트는 메타버스 학습 플랫폼을 주제로 진행하였고 저는 백엔드를 담당하였습니다. 이전 프로젝트 경험을 바탕으로 프론트 구성, 백엔드 API 연동, DB 연동에는 문제가 없었지만 RLS 권한 정책에 문제가 발생하였습니다. 프론트에서 바로 Supabase를 연결하여 RLS 권한 문제가 발생하였고 이를 프론트, 백엔드 API, Supabase 순으로 플로우를 바꿔 실행했더니 정책을 우회하여 접근이 가능하게 되었습니다. 이 문제 이후 모든 로직 흐름을 바꾸어 원활하게 권한 관리를 할 수 있었습니다.

여기서부터 새로쓴 곳
 졸업 이후에도 2D RPG 웹 게임과 청년 대상 정보 플랫폼을 단독으로 기획·개발·배포하며 역량을 확장하였습니다. 두 프로젝트 모두 기획부터 설계, 구현, 테스트, 배포, 인프라 관리까지 전 과정을 직접 수행하였으며, AI 에이전트인 Claude를 활용하여 기획 단계에서 문서를 작성하고, 유사 서비스를 분석하여 최소 MVP를 설계하는 워크플로우를 구성하였습니다.
 개발 과정에서는 GitHub Actions로 CI/CD 파이프라인을 구축하여 빌드, 테스트, 배포를 자동화하였고, QA 과정에서는 Claude의 서브 에이전트를 활용하여 코드 리뷰와 버그 탐지를 수행하였습니다. 자동화 테스트 실행 후 실패 로그를 분석하여 원인을 파악하고 수정하는 사이클을 반복하며, 코드의 정확성과 안정성을 높여나갔습니다.
 인프라 측면에서는 프론트엔드는 Vercel, 백엔드는 Railway로 배포하였으며, Cloudflare를 활용한 도메인 관리 및 보안 설정도 직접 구성하였습니다. 이러한 경험을 통해 단순히 기능을 구현하는 것을 넘어, 서비스를 안정적으로 운영하고 개선하는 역량을 갖추게 되었습니다.
